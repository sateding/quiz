# Анкета клієнта · Dina Titanova

Односторінковий квіз для збору вихідних даних перед дизайн-проєктом.
Статичний сайт: жодного сервера, жодної збірки. Завантажили файли на хостинг — працює.

---

## Швидкий старт

**Подивитися локально.** Просто відкрити `index.html` подвійним кліком не вийде
(браузер блокує локальні скрипти). Треба підняти міні-сервер — один рядок:

```bash
# у папці проєкту
python -m http.server 8000
# далі відкрити http://localhost:8000
```

**Викласти на GitHub Pages** (безкоштовно, HTTPS, оновлюється автоматично):

1. Зареєструватися / зайти на github.com → **New repository** → назва напр. `quiz`,
   тип **Private** або **Public** → *Create*.
2. На сторінці репозиторію: **Add file → Upload files** → перетягнути весь вміст
   цієї папки (не саму папку, а те, що всередині) → *Commit changes*.
3. **Settings → Pages → Source: Deploy from a branch → Branch: `main`, папка `/ (root)`** → *Save*.
4. За 1–2 хвилини з'явиться адреса виду `https://ім'я.github.io/quiz/`.

Далі будь-яка зміна файлів у репозиторії автоматично оновлює сайт.

## Структура

```
index.html          підключає стилі й скрипти, більше нічого
apps-script.gs      код для Google Apps Script (див. нижче)
css/
  fonts.css         локальні шрифти (не залежимо від Google Fonts)
  style.css         ⬅ УВЕСЬ дизайн: кольори, розміри, анімації
js/
  config.js         ⬅ адреса для надсилання, ліміти, контакти студії
  questions.js      ⬅ УВЕСЬ контент: питання, варіанти, підказки
  rooms.js          ⬅ блоки приміщень (кухня, спальня, ванна…)
  store.js          збереження чернетки й надсилання — правити не треба
  app.js            движок квізу — правити не треба
  vendor/           React і htm, лежать локально
img/
  logo.png
  style/            11 фото стилів
  decor/            12 фото декору
  material/         фото оздоблювальних матеріалів
  room/             фото-заставки розділів
fonts/              woff2, ~240 КБ
```

Точки редагування: **`js/questions.js`** і **`js/rooms.js`** — що питаємо,
**`css/style.css`** (блок `:root` угорі) — як це виглядає,
**`js/config.js`** — куди надсилати.

## Як додати питання

Дописати об'єкт у масив `questions` у `js/questions.js`:

```js
{
  id: 'ceiling_material',            // унікальний, стане колонкою в таблиці
  type: 'single',
  section: 'Робоча документація',
  title: 'Чи принциповий для вас матеріал стелі?',
  hint: 'Від цього залежить висота й спосіб розводки світла.',
  options: [
    { id: 'plaster',   label: 'Штукатурка', note: 'Максимальна висота' },
    { id: 'drywall',   label: 'Гіпсокартон' },
    { id: 'stretch',   label: 'Натяжна' },
    { id: 'nomatter',  label: 'Не принципово' }
  ]
}
```

Порядок питань = порядок у масиві. Видалити питання — видалити об'єкт.

### Доступні типи

| `type` | Що показує | Обов'язкові поля |
|---|---|---|
| `cover` | Заставка розділу або вітання | `title`, опційно `lead`, `media`, `facts`, `kicker` |
| `text` | Один рядок | `placeholder` |
| `longtext` | Розгорнута відповідь | `placeholder` |
| `fields` | Кілька полів на екрані | `fields: [{id,label,placeholder,wide}]` |
| `single` | Один варіант із карток | `options: [{id,label,note}]` |
| `multi` | Кілька варіантів | `options`, опційно `max` |
| `chips` | Компактний список предметів | `options: ['Диван','Крісло',…]` |
| `photoSingle` / `photoMulti` | Фото-картки | `options: [{id,label,img}]`, опційно `max` |
| `scale` | Повзунок між полюсами | `left`, `right`, опційно `ticks` |
| `colors` | Палітра кольорів | `options: [{id,label,hex}]` |
| `repeater` | Рядки, які клієнт додає сам | `fields`, `addLabel` |
| `upload` | Завантаження фото-референсів | — |
| `review` | Екран перевірки перед надсиланням | — |

Спільні поля: `section`, `hint`, `required`, `showIf`.

### Показувати питання лише за умови

```js
showIf: (a) => a.object_type === 'house'
```

`a` — це всі відповіді, зібрані досі, за ключами `id`.

## Як змінити вигляд

Майже все керується змінними на початку `css/style.css`:

```css
--bg:        #FBF9F6;   /* тло сторінки */
--ink:       #17150F;   /* основний текст */
--gold:      #C2A24B;   /* акцент із рамки логотипа */
--gold-deep: #856A2C;   /* той самий акцент для тексту */
```

Змінили `--gold` — перефарбувався весь сайт: рамки обраних фото, прогрес-лінія,
підписи розділів, галочки.

Шрифти: заголовки — Cormorant Garamond, інтерфейс — Manrope.
Замінити можна в `css/fonts.css` і в двох рядках `font-family` у `style.css`.

## Приміщення: як працює умовний показ

У розділі «Планування» клієнт відмічає, які приміщення в нього будуть
(питання `rooms_list`). Далі анкета показує блоки **тільки для обраних кімнат**.

Кожне приміщення в `js/rooms.js` — це виклик `room(...)`:

```js
room('kitchen', 'Кухня',
  'Підказка на першому екрані',
  ['Острів', 'Барна стійка', …],        // список предметів
  [ { id:'hob', label:'Варильна поверхня', placeholder:'…' }, … ])
```

Друга аргументом іде назва — вона має **точно збігатися** з варіантом
у списку `rooms_list` у `questions.js`. Якщо назви розійдуться, блок не покажеться.

Усього 89 екранів; типова квартира з 7 приміщеннями бачить близько 74.

## Надсилання відповідей

Уже створено в Google Drive, у папці «Dina Titanova — Квіз (проєкт)»:

- таблиця **«Анкети клієнтів · Dina Titanova»** — сюди падають рядки;
- папка **«Референси клієнтів»** — сюди складаються фото, по підпапці на клієнта.

Лишилося запустити приймач — інструкція на початку файлу `apps-script.gs`.
Коротко: відкрити таблицю → Розширення → Apps Script → вставити код →
вписати свій email → Розгорнути як веб-застосунок → скопіювати URL →
вставити його в `js/config.js` у поле `endpoint`.

Поки `endpoint` порожній, квіз працює в демо-режимі: відповіді нікуди не йдуть,
але PDF-бриф формується як зазвичай.

**Що робить приймач:** дописує рядок у таблицю (колонки створюються самі, під
кожне питання), складає фото в папку клієнта з датою й іменем, надсилає вам лист
із повним брифом і посиланнями.

## Що вміє зараз

- 89 екранів, згрупованих у 8 розділів; блоки приміщень показуються за умовою
- автозбереження у браузері: можна закрити вкладку й повернутися
- фото-референси зберігаються в IndexedDB і не втрачаються при перезавантаженні
- екран перевірки перед надсиланням із переходом до будь-якої відповіді
- PDF-бриф: векторний текст, фірмова шапка, розділи по приміщеннях
- клавіатура: `Enter` — далі, `Tab` — між варіантами
- адаптив: десктоп / планшет / телефон
- повага до `prefers-reduced-motion`
- контраст тексту ≥ 4.5:1
- жодних зовнішніх запитів: React, шрифти й зображення лежать поруч

## Переїзд на інший хостинг

Сайт статичний і не має збірки, тому переносити просто: скопіювати весь вміст
папки на сервер. Але є чотири речі, які варто перевірити.

**1. Логотип у PDF.** У `apps-script.gs` є `LOGO_URL` з адресою на GitHub Pages.
Якщо старий сайт вимкнете — поміняйте адресу на новий домен і перерозгорніть
скрипт, інакше в шапці PDF буде порожнє місце.

**2. Кеш браузера.** GitHub Pages віддає файли з коротким кешем, багато хостингів —
з довгим. Після оновлення клієнти можуть тиждень бачити стару версію. Якщо
плануєте часто правити анкету, додавайте версію до підключень у `index.html`:

```html
<link rel="stylesheet" href="css/style.css?v=2">
<script src="js/app.js?v=2"></script>
```

і збільшуйте число після кожної зміни.

**3. HTTPS.** Технічно анкета працює і по http, але сучасні браузери показують
попередження на сторінках із формами. Беріть хостинг із безкоштовним сертифікатом.

**4. Підпапка — можна.** Усі шляхи в проєкті відносні, тому анкета однаково
працює і в корені домену, і за адресою виду `site.com/anketa/`.

**Що НЕ треба міняти:** адресу `endpoint` у `js/config.js`. Apps Script приймає
запити з будь-якого домену, тож переїзд його не зачіпає.
